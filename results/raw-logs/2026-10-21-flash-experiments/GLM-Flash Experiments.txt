## ZFS Copy-on-Write Fundamentals

ZFS is a transactional, copy-on-write filesystem. The core principle: ZFS never overwrites existing data in place. Instead, when you modify data:

1. The modified block is written to a **new, free location** on disk
2. A new copy of the **indirect block** (metadata pointing to the data block) is written, pointing to the new data block location
3. This propagates up the tree — the parent of the indirect block gets rewritten, and so on
4. Eventually, the root of the tree (the dataset's objset, then the MOS — Meta Object Set, then the uberblock) gets updated

This means every write transaction creates a new root for the entire pool's metadata tree. The uberblock is the root of trust.

## ZFS Copy-on-Write Fundamentals

ZFS is fundamentally a copy-on-write filesystem. This means:
- Data is never modified in place
- When a block is modified, a new copy of the block is written to a new location on disk
- The old block remains until it's no longer referenced
- Updates happen transactionally

## The Transaction Group (TXG) Model

ZFS operates in transaction groups (txgs). There are three txg states:
- Open: accepting new writes
- Quiescing: no new writes, waiting for in-flight operations

## ZFS Copy-on-Write Fundamentals

ZFS is fundamentally a copy-on-write filesystem. This means:
- Data is never modified in place
- When a block is modified, a new copy of the block is written to a new location on disk
- The old block remains until it's no longer referenced
- This is what makes snapshots nearly free
